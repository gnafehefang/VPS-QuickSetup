# VPS-QuickSetup

新装系统的 VPS 一键初始化脚本（Debian / Ubuntu），交互式菜单，每一步可重复执行，已经配置过的会自动跳过。

## 使用

以 root 登录新 VPS 后执行（非 root 会自动通过 sudo 重新运行）：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/gnafehefang/VPS-QuickSetup/main/setup.sh)
```

远程入口需要 `bash`、`curl`、`tar` 和 gzip 解压支持。入口先把 `main` 分支的完整仓库归档下载到临时目录，再运行归档内的入口和全部模块，不逐个下载浮动分支上的功能文件；下载、解压或模块预检失败时不进入菜单。退出后清理临时目录，非 root 通过 sudo 重新运行时仍使用同一套文件。

本地运行需保留完整仓库（`setup.sh` 和 `scripts/`），不要只复制入口文件；入口根据自身位置寻找模块，不依赖当前工作目录，也不会在本地文件缺失时悄悄下载另一版覆盖：

```bash
bash /path/to/VPS-QuickSetup/setup.sh
```

## 项目结构

```text
setup.sh                       # 加载预检、本地/远程启动入口
scripts/
  common.sh                    # 默认配置、提示、输入、提权和通用备份
  ssh-common.sh                # SSH 配置校验、事务快照、回滚及 socket 切换
  keys-common.sh               # 公钥校验、写入和账号查询
  login-check.sh               # 登录测试端口选择和确认
  01-update.sh                 # 系统更新
  02-timezone.sh               # 时区与自动校时检查
  03-pubkey.sh                 # 添加公钥
  04-admin.sh                  # 创建管理员
  05-ssh-port.sh               # SSH 端口与旧端口关闭
  06-ufw.sh                    # 防火墙
  07-fail2ban.sh               # fail2ban 及端口同步
  08-swap.sh                   # swap
  09-tcp.sh                    # TCP 调优
  10-ssh-password.sh           # 禁用密码登录
  11-ssh-root.sh               # 禁用 root 登录
  12-hostname.sh               # hostname
  13-all.sh                    # ALL 安全顺序编排
  14-status.sh                 # 当前状态和脱敏账号报告
  menu.sh                      # 菜单和选项分发
tests/
  regression.sh                # 功能与失败处理回归
  bootstrap.sh                 # 模块加载、远程启动、提权与清理回归
```

功能文件通过入口在同一个 Bash 进程中 `source` 加载，不单独执行，以保留本轮管理员、目标端口、旧端口和登录确认等状态。加载前对已登记模块逐个检查文件和 Bash 语法，全部通过才加载；不执行目录内未登记的脚本。菜单编号、防锁死检查、备份及回滚行为保持不变。

维护已有功能时修改对应模块；新增功能时，在 `setup.sh` 的预检清单和显式加载清单中登记，再接入 `scripts/menu.sh`。需加入 ALL 时同时更新 `scripts/13-all.sh` 的安全顺序和相关回归测试。显式 source 路径也供 ShellCheck 跟踪跨文件依赖。

## 菜单

| 选项 | 功能 | 说明 |
|---|---|---|
| 1 | 系统更新 + 基础工具 | `apt update && apt upgrade`，安装 curl wget sudo 等 |
| 2 | 设置时区 + 自动校时 | 回车默认 `Asia/Singapore`；时区正确也继续检查 NTP，未启用时执行 `timedatectl set-ntp true` 并复核；分别报告自动校时启用与时钟同步状态 |
| 3 | 添加公钥 | 粘贴公钥，或从 `https://github.com/<用户名>.keys` 拉取；所选用户已有有效公钥时，默认 `0` 保留并跳过，也可继续添加；粘贴内容或 GitHub 用户名留空时，重新校验现有公钥，通过才跳过；重复的不加，写入或权限设置失败、全部无效时返回失败 |
| 4 | 创建 admin 用户 | 默认用户名 `admin`，已有同名组时复用；复制 root 的公钥，加入 sudo 组，可选免密 sudo（`/etc/sudoers.d/90-<用户>`，visudo 校验）；账户、公钥或 sudo 配置失败立即停止本步骤，不标记为可用管理员 |
| 5 | 修改 SSH 端口 | 每次进入时从 `49152-65535` 中随机推荐一个端口，提示范围及本次候选值，回车采用；可手动输入 `1-65535`（不接受前导零），输入当前唯一端口可保持不变。随机选择避开当前 SSH 端口和已有 TCP 连接/监听的本地端口，应用前复核占用；无法生成随机默认值时仍可手动输入。UFW 已启用时先放行新端口；过渡期保留旧端口，确认新端口能登录后再关闭（sshd + UFW）；自动处理 `ssh.socket` |
| 6 | 安装 UFW | 启用前自动放行当前 SSH 端口，默认拒绝入站 |
| 7 | 安装 fail2ban | `/etc/fail2ban/jail.d/sshd.local`：端口跟随 SSH，systemd 后端，10 分钟内失败 5 次封 1 小时 |
| 8 | 设置 swap | 已有 swap 则跳过；内存 <2G 建 2G，2–4G 与内存相同，>4G 建 4G；`swappiness=10` |
| 9 | TCP 调优 | 开启 BBR + fq + `tcp_mtu_probing=1` |
| 10 | 禁用密码登录 | 没有任何用户配置有效公钥时拒绝执行，并要求确认已测试密钥登录 |
| 11 | 禁用 root 登录 | 需要一个带公钥的 sudo 用户；写入 `PermitRootLogin no` + `AllowUsers <用户>`，可选锁定 root 密码；root 已禁用但白名单未设置或不是所选用户时，仍需确认并完成白名单配置 |
| 12 | 修改 hostname | 输入新主机名；回车默认 `Host` + 当天系统日期（`YYYYMMDD`），如 `Host20261029`；保留大小写，允许 1-63 位字母、数字和连字符，首尾不能是连字符 |
| 13 | ALL | 按安全顺序：1 → 2 → 3 → 4 → 5 → 6 → 7 → 8 → 9 → **暂停，另开窗口测试新端口 + admin 登录** → 10 → 11 → 关闭旧端口 → 12 |
| 14 | 查看当前状态 | SSH 策略、登录及带公钥账号数与脱敏公钥清单、TCP/UDP 监听、带编号的 UFW 规则、fail2ban，以及可核对的本机 `~/.ssh/config` 片段 |
| 0 | 退出 | |

## 防锁死设计

- SSH 配置统一写入 `/etc/ssh/sshd_config.d/00-quicksetup.conf`，在主配置第一行直接 `Include` 该文件以保证单值配置优先级；保留原有其他配置。修改前备份到 `/root/quicksetup-backup/<时间>/`，`sshd -t` 校验失败自动回滚，不会重启 sshd。
- 改端口时新旧端口并存，确认新端口能登录后才关旧端口。
- SSH 重启 / 重载后检查服务状态和预期监听端口，通过后才清理快照、关闭旧防火墙入口；失败则恢复原配置并尝试重新启动，恢复失败时保留快照供人工处理。
- 切换 `ssh.socket` 时同时备份和处理 Ubuntu 遗留的 `00-socket.conf` / `addresses.conf`，重新加载 systemd；失败时恢复文件和原 socket 启用、运行状态。
- 临时快照、配置复制或持久备份失败时拒绝修改 SSH；同一轮运行保留每个文件的首份持久备份。恢复时先在目标文件系统完整暂存，再替换配置，暂存失败不删除现有目录；缺失目录会按原状态恢复。未完成恢复的快照不会被下一次操作覆盖。受管主配置或目录使用符号链接时需人工处理。
- 禁用密码 / 禁用 root 前都会检查公钥。ALL 在第 9 步后只确认一次目标端口上所选管理员的密钥登录和 `sudo -i` 测试，第 10、11 步仅对本轮同一账号、同一端口复用确认；确认不写入磁盘、不跨运行保留。第 11 步换用户或端口时重新测试，单独运行菜单 10 / 11 仍要求确认。测试命令优先使用本轮选定且仍在监听的端口，否则使用仍在监听的当前连接端口或配置端口，并查询服务器 IP；命令限制为公钥认证，避免误把密码登录当作测试通过。无法确定端口或地址时不继续收紧。
- 登录测试提示中的 SSH 命令与 `sudo -i` 各占一行，命令行没有提示前缀或尾随说明，便于逐条复制；实际测试确认与后续收紧顺序不变。
- `AllowUsers` 未设置表示没有用户名白名单，不表示只允许 admin；仍受其他 SSH 策略限制。第 11 步只有在 root 已禁用、白名单及连接上下文校验均符合所选管理员时才跳过。状态中的 SSH 示例优先选择已配置的管理员，必须有有效公钥且符合已知白名单；不再因白名单为空而直接填 root。存在复杂准入规则或读取失败时不猜测示例用户名，仍需另开终端验证。
- SSH 多值配置在读取时按首次出现顺序去重：`6090 6090` 显示为 `6090`，`admin admin` 显示为 `admin`，不同端口和用户仍完整保留。重复值可能来自显式 Include 与通配符 Include 重复加载同一文件，并不表示有两个同名账号；去重同时用于状态、示例及幂等检查，不自动重写原有 Include 配置。
- 跳过添加公钥只接受所选用户经 `ssh-keygen -l` 校验通过的现有公钥，不以文件存在或非空代替校验；跳过前再次检查。没有有效公钥时，回车或输入 `0` 都返回失败；实际拉取或写入失败不会因旧公钥存在而被当作跳过，仍会停止 ALL。保留现有公钥不代表已验证登录，后续仍需另开窗口测试管理员登录和 sudo。
- ALL 在添加公钥或创建管理员失败时立即停止，不继续修改端口或收紧 SSH；创建管理员后及登录测试提示前，复核所选非 root 用户、有效公钥和 sudo 组身份，不回退成 root 或沿用上次管理员。
- 收紧登录前用 `sshd -T` 和当前连接参数对应的 `sshd -T -C` 核对 root、带公钥用户的有效策略；若存在 `Match` 或非标准 `Include`，拒绝自动收紧，需先人工审查。已有其他 `AllowUsers` 条目导致“只允许所选用户”无法成立时也会回滚。
- **执行 10、11、关闭旧端口前，务必另开一个终端窗口测试登录成功，当前窗口不要关。**

## 生成的文件

- `/etc/ssh/sshd_config.d/00-quicksetup.conf`
- `/etc/fail2ban/jail.d/sshd.local`
- `/etc/sysctl.d/99-quicksetup-swap.conf`、`/etc/sysctl.d/99-quicksetup-tcp.conf`
- `/etc/modules-load.d/quicksetup-bbr.conf`
- `/etc/sudoers.d/90-<用户>`
- `/swapfile`
- `/etc/hostname`（更新静态和当前主机名）、`/etc/hosts`（维护一条带标记的本机解析记录，保留原有记录）

修改 hostname 前会备份配置；设置或校验失败时尝试恢复。默认日期在进入该步骤时读取，按 VPS 当前时区计算，不是脚本发布时的固定日期。

第 2 步沿用系统中 `timedatectl` 可识别的现有校时服务，不自动安装、替换服务或改写其服务器配置。NTP 已启用时不重复切换服务；未启用或状态读不到时尝试启用并重新核对 `NTP=yes`。明确无可用服务、启用失败或复核失败时返回失败并提示原因。启用成功不等于时钟立即同步：`NTPSynchronized=no` 时提示尚未同步，读不到时提示无法确认，不强制等待或把它报为已同步。时区设置和 NTP 是不同操作，启用 NTP 失败不会撤销已经成功设置的时区。

当前状态的 `[基础信息]` 分别读取 `NTP` 和 `NTPSynchronized`，显示“自动校时已启用”和“系统时钟已同步”。两项独立判断：`yes` 为绿色，`no` 或“未知 (读取失败)”为红色；命令失败、空值和非预期值不能视为有效状态。查看状态不会启用或修改校时服务。

脚本里不包含任何密钥或密码，公钥在运行时输入。

## 核查已有账号和端口

脚本只按菜单 4 输入的用户名创建管理员，不会固定创建 `opc` 或 `ubuntu`。它们可能由云镜像、cloud-init 或重装工具预置，但仅凭用户名无法确定来源，也不能据此排除入侵。Linux 正常运行还需要系统服务账号，不应只保留 root 和 admin 两个系统账号；SSH 登录范围应通过经过验证的准入策略限制。

菜单 14 只显示“登录及带公钥账号”的数量和明细，不显示系统账号总数。明细隐藏使用 `nologin` / `false` / `sync` / `true` 且没有非空标准公钥文件的服务账号；不按 UID 阈值排除自定义登录账号。root 及其他 UID 0 账号始终保留；服务账号若有非空公钥文件或公钥文件符号链接也保留，异常仍标记，不因隐藏服务账号而掩盖密钥。分类只用于显示，不等于实际 SSH 准入，禁用 root 登录也不会删除 root 账号。

每个展示账号只列标准 `authorized_keys` / `authorized_keys2` 文件中的去重有效公钥数和脱敏 SHA256 指纹。指纹正文仅显示首尾各 6 个字符，中间替换为 `********`；不输出完整指纹、公钥原文、注释、文件路径、UID 或 shell。重复公钥按完整指纹去重后再脱敏，显示相似不影响计数；异常短指纹全部遮盖。`0+?` 等表示展示账号还有异常路径、不可读文件或校验失败，仅汇总提示一次，不能当作确定没有密钥。非标准公钥文件、`AuthorizedKeysCommand`、用户 CA 及 `Match` 中的其他来源不在统计范围。公钥文件存在不代表该账号获准 SSH 登录，也不是入侵检测结论；本节只读展示，不修改账号或密钥。

当前状态主标题使用加粗亮青色、上下宽分隔栏和两行前置留白，便于回看终端输出时定位。状态页按基础信息、SSH 全局策略、账号与公钥、监听、UFW、fail2ban、本机 SSH 配置分区，分区之间留空行，使用无色的 `[标题]`，内容统一缩进 4 格；密钥指纹和 SSH 配置属性再缩进一级，错误提示也归入对应分区。`root 登录=no`、`密码登录=no`、`密钥登录=yes`、`键盘交互认证=no` 按安全目标显示绿色，反向或未知值显示红色，不以读不到值代替安全值。`AllowUsers` 空白会明确标红解释；能核对到单个非 root 示例用户时才标绿。UFW 启用和 fail2ban sshd jail 查询成功显示绿色，未启用/未安装或无法确认时显示红色。这些状态不能替代其他认证规则、连接上下文和实际登录测试。

UFW 步骤保留原有规则，不执行 reset；确认新 SSH 入口可用后，只删除本轮识别的旧 SSH 端口规则。因此其他历史规则或以前运行遗留的端口仍可能存在。菜单 14 将规则和实际监听分别显示，监听还包括回环和系统服务，不代表对应端口可从公网访问，也不能替代云防火墙和完整 netfilter 审计。

SSH 全局策略、TCP / UDP 监听及 UFW 防火墙末尾的说明与上一项之间留空行，以 `[说明]` 开头，长句分行显示。

发现陌生账号或端口时，先保留当前连接及日志，通过控制台核对镜像/重装记录、cloud-init 配置及日志、认证成功记录，再将清单里的指纹与自己和云控制台配置的公钥比较。只读核查示例：

```bash
sudo getent passwd
sudo ss -lntup
sudo ufw status numbered
sudo journalctl -u ssh -u sshd --no-pager -n 200
sudo last -Fai | head -50
```

确认某条规则确实多余且不会影响当前 SSH 或其他服务后，再按规则编号人工删除并复查 IPv4 / IPv6；不要直接清空防火墙或批量删除用户。账号创建时间不能靠公钥文件时间可靠推定，日志也可能不完整。若存在无法解释的公钥或成功登录记录，应进一步调查；确认失陷时，不要把删除账号或规则当作已恢复可信，应从可信环境保全证据、隔离并从可信镜像重建，轮换相关凭据。核查输出在分享前应隐藏不必要的 IP、用户名及其他敏感信息。

## 回归测试

```bash
for file in setup.sh scripts/*.sh tests/*.sh; do
  bash -n "$file" || exit 1
done
bash tests/regression.sh
bash tests/bootstrap.sh
# 可选, 需已安装 ShellCheck; -x 沿入口检查被 source 的模块
shellcheck -x --severity=warning setup.sh tests/*.sh
```

测试通过临时目录和命令模拟验证失败处理，不安装软件、不改动真实 SSH / UFW / systemd 配置。启动测试使用本地生成的归档和模拟 curl / sudo，不下载或执行远程代码。实际 VPS 上仍需另开窗口测试登录。
